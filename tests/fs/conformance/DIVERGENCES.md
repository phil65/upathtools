# Intentional Divergences from `fsspec`

`upathtools.fs` ports selected behavioural algorithms from `fsspec` (tracked per module via
`__fsspec_sync__` against `FSSPEC_SYNC_VERSION`) and bridges bidirectionally via
`from_fsspec()` / `to_fsspec()`, but intentionally diverges where `fsspec` has known typing,
isolation, error-handling, or free-threading hazards.

## How to read this table

- **fsspec behaviour**: What upstream `fsspec` (at `FSSPEC_SYNC_VERSION`) does.
- **upathtools.fs behaviour**: What `upathtools.fs` does instead, including how the `to_fsspec`
  or `from_fsspec` adapters translate at the boundary when applicable.
- **why**: The design reason for the divergence.
- **test that pins it**: One or more pytest node IDs (`path/to/test.py::test_name` or
  `path/to/test.py::TestClass::test_method`) that assert this behaviour.
  `tests/fs/conformance/test_divergences.py` parses this table and verifies that every listed
  test ID exists, so entries cannot silently rot.

## When an `fsspec` bump changes a row

1. Run `python scripts/check_fsspec_sync.py` to print the locked vs. installed `fsspec` versions,
   all synced modules, and the GitHub compare URL.
2. Run `uv run pytest tests/fs/` to see if any conformance test fails or any strict `xfail`
   in `tests/fs/test_from_fsspec.py` turns into an `XPASS`.
3. Inspect the upstream diff for each affected symbol:
   - If `fsspec` fixed a backend quirk (e.g. a strict `xfail` starts passing), remove the `xfail`
     and delete or update the corresponding row here.
   - If `fsspec` changed behaviour we intentionally still reject (or adopted behaviour we want
     to match), update the implementation, tests, and the row in this table accordingly.
4. Update `FSSPEC_SYNC_VERSION` in `src/upathtools/fs/_sync.py` (and any changed module
   `__fsspec_sync__` notes), then verify `test_sync_notes.py` and `test_divergences.py` pass.

## Divergence matrix

| fsspec behaviour | upathtools.fs behaviour | why | test that pins it |
| --- | --- | --- | --- |
| `_Cached` metaclass (`cachable = True`) caches instances globally by `(cls, pid, thread_id, ...)` with strong references; `MemoryFileSystem.store` and `pseudo_dirs` are class-level mutable globals shared across instances and threads. | No `_Cached` metaclass; every constructor returns an isolated instance and `AsFsspecFileSystem.cachable = False`. Each `MemoryFS()` owns a private `MemoryStore` (explicit `MemoryFS(store=...)` opts into sharing). Opt-in reuse lives in `FilesystemPool`, keyed by a `WeakKeyDictionary` of running event loops rather than thread IDs. | Prevents cross-test/cross-caller state leaks, memory retention of live clients/credentials, free-threading races on globals, and stale loop-bound clients across sequential `asyncio.run()` calls on one thread. | `tests/fs/test_memory.py::test_memory_instance_isolation`, `tests/fs/test_memory.py::test_memory_shared_store`, `tests/fs/test_pool.py::test_pool_isolates_two_sequential_asyncio_run_calls_on_same_thread`, `tests/fs/test_to_fsspec.py::test_fsspec_class_for_caches_per_class_and_protocol` |
| `AbstractFileSystem.exists()` uses bare `except: return False` and `isfile()`/`isdir()` catch broad `Exception: return False`, swallowing auth failures, timeouts, and bugs. | `exists()`, `is_file()`, and `is_dir()` catch only `FileNotFoundError` and `NotADirectoryError`; `PermissionError`, `FSTimeoutError`, and all other errors propagate. | Silently turning permission errors or network timeouts into `False` hides real outages and can cause destructive fallback branches (e.g. overwriting an existing resource). | `tests/fs/test_base.py::test_exists_is_file_is_dir_propagate_non_missing_errors` |
| `AbstractFileSystem.find()` / `AsyncFileSystem._find()` on a single file returns `{path: {}}` (missing `"name"`, `"type"`, `"size"`). | `AsyncFS.find(file_path)` returns `[FileInfo(...)]` with complete metadata (`path`, `type="file"`, `size`, timestamps). | Callers can rely on uniform `FileInfo` records without special-casing empty dicts when `find()` is pointed at a single file. | `tests/fs/test_memory.py::TestMemoryFSContract::test_find_and_find_paths`, `tests/fs/test_local.py::TestLocalFSContract::test_find_and_find_paths` |
| `ls(file_path)` returns `[info]` (or `[file_path]` when `detail=False`) instead of raising an error. | Core `AsyncFS.ls(file_path)` raises `NotADirectoryError` (and `FsspecAdapter.ls()` normalizes fsspec's single-file `[info]` response to `NotADirectoryError`). The outbound `to_fsspec()` adapter catches `NotADirectoryError` and restores fsspec's `[info]` / `[path]` behaviour for fsspec callers. | Matches POSIX `os.scandir`/`listdir` semantics and eliminates the ambiguity between a directory containing one file and a file itself, while preserving full compatibility through `to_fsspec()`. | `tests/fs/test_memory.py::TestMemoryFSContract::test_error_types`, `tests/fs/test_from_fsspec.py::test_s3_style_empty_root_marker_path_handling`, `tests/fs/test_to_fsspec.py::test_to_fsspec_ls_on_file_and_directory` |
| `ls()`, `find()`, and `glob()` accept a polymorphic `detail: bool` flag that changes the return type between `list[str]`, `list[dict]`, and `dict[str, dict]`. | No `detail` parameter on core `AsyncFS` methods; separate statically typed methods are provided (`ls()` vs `ls_names()`, `find()` vs `find_paths()`, `glob()` vs `glob_paths()`). `to_fsspec()` restores `detail=` on `_ls`/`_find`/`_glob` for fsspec compatibility. | Eliminates union return types and defensive `isinstance(..., dict)` branches across callers, enabling strict static typing. | `tests/fs/test_base.py::test_no_detail_polymorphism_and_no_sync_property`, `tests/fs/test_to_fsspec.py::test_to_fsspec_asynchronous_mode` |
| `cp`/`copy`/`mv` use shell-like "copy into existing directory" rules with trailing-slash ambiguity and list/glob expansion. | Core `AsyncFS.copy(src, dst)` and `AsyncFS.move(src, dst)` follow `pathlib.Path` exact-target semantics (`dst` is always the exact target; copying a file onto an existing directory raises `IsADirectoryError`; directory merges validate conflicts before writing). Outbound `to_fsspec(fs)` still provides fsspec's `cp`/`mv` semantics because fsspec's own `AsyncFileSystem` algorithms run on our `_cp_file`/`_rm`/`_mkdir` primitives. | Exact-target semantics remove trailing-slash footguns and make programmatic copy/move predictable, while `to_fsspec()` preserves 100% `fsspec.tests.abstract` conformance. | `tests/fs/test_memory.py::TestMemoryFSContract::test_copy_file_and_tree`, `tests/fs/test_memory.py::TestMemoryFSContract::test_move_file_and_tree`, `tests/fs/conformance/test_fsspec_abstract.py::TestToFsspecMemoryFS::test_copy_file_to_existing_directory`, `tests/fs/conformance/test_fsspec_abstract.py::TestToFsspecMemoryFS::test_copy_directory_to_existing_directory` |
| `AbstractFileSystem.mv(..., recursive=True)` delegates to `copy` + `rm` without pre-flight validation and has broken on directory trees / pseudo-directories. | `AsyncFS.move()` moves both files and full directory trees cleanly: the default implementation copies first and removes `src` only if the copy succeeds; `MemoryFS.move()` is atomic under its lock; `LocalFS.move()` uses `Path.replace()` with `EXDEV` and directory-merge fallbacks; `to_fsspec(fs).mv(..., recursive=True)` works on trees. | Guarantees directory tree moves work across all backends and never leave a partially deleted source tree on mid-copy failure. | `tests/fs/test_memory.py::test_memory_atomic_subtree_move`, `tests/fs/test_base.py::test_default_base_move_leaves_source_intact_on_mid_copy_failure`, `tests/fs/test_local.py::test_local_move_cross_device_fallback`, `tests/fs/test_to_fsspec.py::test_to_fsspec_mv_file_and_directory` |
| `DirFileSystem.__init__` raises `ValueError` if `self.asynchronous != fs.asynchronous` and does not reject `..` path-traversal escapes above its root prefix. | `DirFS` has no `asynchronous` attribute, wraps any `AsyncFS[TInfo]` preserving `TInfo` subclasses, and lexically rejects any `..` segment escaping above its root with `PathEscapeError` before performing any I/O. | Removes async/sync wrapper friction and prevents accidental lexical escapes outside a rooted workspace prefix. | `tests/fs/test_dirfs.py::test_dirfs_lazy_root_capabilities_and_close_wrapped`, `tests/fs/test_dirfs.py::test_dirfs_escape_attempts_raise_before_io_and_touch_nothing`, `tests/fs/test_dirfs.py::test_dirfs_preserves_tinfo_subclass_and_rewrites_paths` |
| `LocalFileSystem` is globally cached and `fsspec.core.open_files` mutates `fs.auto_mkdir` on the shared instance; writes open the target file directly so concurrent readers can observe partial/torn contents. | `LocalFS(auto_mkdir=...)` stores `auto_mkdir` strictly per instance (default `True`, never mutated globally); `write_bytes(..., mode="overwrite")` writes to a sibling `O_EXCL` temp file and swaps via atomic `Path.replace()`, while `mode="create"` uses atomic `O_EXCL` (`"xb"`). | Safe under multi-threading / PEP 703 free-threading: per-instance config cannot race and readers never observe torn files. | `tests/fs/test_local.py::test_local_auto_mkdir_per_instance_isolation`, `tests/fs/test_local.py::test_local_atomic_write_no_temp_files_and_no_partial_reads`, `tests/fs/test_local.py::test_local_create_mode_race_exactly_one_winner` |
| `fsspec.asyn.get_loop()` spawns a hidden global `"fsspecIO"` daemon thread with a lazily allocated `_lock`; `mirror_sync_methods` mutates instance `__dict__` at runtime; `reset_after_fork()` declares `global lock` instead of `global _lock`, leaking the parent lock into forked children. | Synchronous calls go through an explicit, statically typed `SyncFS(fs, runner=...)` facade backed by an explicit `LoopRunner` (with opt-in `get_default_runner()` for scripts; no `fs.sync` property and no `__dict__` mirroring). `to_fsspec()` binds the `LoopRunner` loop (never spawning `"fsspecIO"`), locks are created eagerly, same-loop re-entry raises `RuntimeError`, and `os.register_at_fork` resets all locks and live runners properly. | Keeps static typing (`ty`) 100% accurate without override ignores, gives explicit thread lifecycle control, and fixes upstream fork-deadlock and free-threading lock-init bugs. | `tests/fs/test_sync.py::test_syncfs_properties_and_default_runner`, `tests/fs/test_sync.py::test_syncfs_drift_guard_matches_asyncfs_methods_and_signatures`, `tests/fs/test_base.py::test_no_detail_polymorphism_and_no_sync_property`, `tests/fs/test_to_fsspec.py::test_to_fsspec_sync_uses_runner_loop_never_fsspec_io_thread`, `tests/fs/test_runner.py::test_runner_fork_safety`, `tests/fs/test_runner.py::test_runner_reentry_from_own_loop_raises_and_no_warning` |
| Returns mutable, untyped `dict[str, Any]` entries with inconsistent backend key aliases (`name`/`Key`, `mtime`/`modified`/`LastModified`/`updated`, `created`/`CreationTime`, `size`/`Size`, `etag`/`ETag`, `type="dir"`/`"link"`). | Returns `@dataclass(frozen=True, slots=True, kw_only=True)` `FileInfo` (no `__getitem__`, immutable `MappingProxyType` `extra`). `FileInfo.from_fsspec_dict()` normalizes provider key aliases and timestamps into canonical fields while preserving unknown/unparsable entries in `extra`; `to_fsspec_dict()` round-trips back for interop. | Typed attribute access, immutability under free-threading, and a single normalization boundary instead of ad-hoc key fallbacks at every call site. | `tests/fs/test_types.py::test_file_info_is_frozen_slots_kw_only`, `tests/fs/test_types.py::test_file_info_extra_is_read_only_and_not_aliased`, `tests/fs/test_types.py::test_from_fsspec_dict_s3_style`, `tests/fs/test_types.py::test_from_fsspec_dict_gcs_style`, `tests/fs/test_types.py::test_from_fsspec_dict_local_style`, `tests/fs/test_types.py::test_from_fsspec_dict_type_normalization`, `tests/fs/test_types.py::test_file_info_fsspec_dict_round_trip` |

| `AsyncFileSystem._walk()` lists directories sequentially one by one and `_du()` performs N+1 `_info()` calls after `_find()`. | `AsyncFS.walk()` lists sibling directories concurrently via `run_bounded()`, and `AsyncFS.du()` computes sizes in a single pass from `find()` `FileInfo` metadata without extra `info()` calls. | Avoids sequential latency amplification on remote/sandbox filesystems and eliminates redundant per-file metadata RPCs. | `tests/fs/test_base.py::test_du_runs_single_pass_without_per_file_info_calls`, `tests/fs/test_memory.py::TestMemoryFSContract::test_walk` |
